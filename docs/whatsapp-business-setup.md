# WhatsApp Business Setup

This application treats WhatsApp as an organization-owned support channel. Platform emails such as team invites come from Fitz Industries infrastructure, but customer support WhatsApp messages must use the customer's own WhatsApp Business phone number.

## Required Meta Assets

Each organization needs:

1. A Meta Business account.
2. A Meta app with the WhatsApp product enabled.
3. A WhatsApp Business Account connected to the app.
4. A WhatsApp phone number.
5. The phone number ID from Meta.
6. A permanent access token or system-user token with WhatsApp messaging permissions.
7. A webhook verify token generated by the organization/admin and saved in this app.

## Local Testing Requirement

Meta cannot call `localhost` directly. For local testing, expose the Hono API with a public HTTPS tunnel such as ngrok or Cloudflare Tunnel.

Example local callback URL after tunneling:

```txt
https://your-public-tunnel.example.com/api/webhooks/whatsapp
```

For production, use the deployed Hono API URL:

```txt
https://api.yourdomain.com/api/webhooks/whatsapp
```

## Meta Setup Steps

1. Open Meta for Developers.
2. Create or select a business app.
3. Add the WhatsApp product.
4. Add or select the organization's WhatsApp phone number.
5. Copy the phone number ID.
6. Create a webhook verify token. This can be any strong random string.
7. In the Meta WhatsApp webhook settings, set the callback URL to `/api/webhooks/whatsapp` on the public API host.
8. Set the webhook verify token to the same value saved in this app.
9. Subscribe the webhook to the `messages` field.
10. Generate a long-lived system-user access token with WhatsApp messaging permissions.

## App Channel Setup

In `/settings/channels`, enter:

1. Name: a friendly label such as `Main WhatsApp Support`.
2. Phone number: the customer-facing WhatsApp number.
3. Phone number ID: copied from Meta.
4. Access token: the long-lived token from Meta. This is encrypted before storage.
5. Webhook verify token: the same token configured in Meta.
6. Active: enabled once ready to receive messages.

## Current Runtime Behavior

Inbound WhatsApp messages are handled by the Hono webhook at `/api/webhooks/whatsapp`.

When a customer messages an active organization WhatsApp number, the app:

1. Looks up the matching active WhatsApp channel by Meta phone number ID.
2. Creates or reuses a customer record by WhatsApp sender phone number.
3. Creates or reuses an open WhatsApp conversation.
4. Stores the inbound message.
5. Ensures the conversation has an open ticket so it appears in the support queue.

## Future Bot Integration

Botpress, Voiceflow, or another AI bot should sit between inbound message storage and agent handoff.

Recommended future flow:

1. Inbound WhatsApp message arrives.
2. Store customer, conversation, message, and ticket.
3. If the channel has a bot configured, send the message to the bot provider.
4. Store the bot response as a bot/system message.
5. Send the bot response back through WhatsApp.
6. If the bot escalates, assign the ticket to the team queue or an agent.

Keep the WhatsApp channel table as the place for provider-specific configuration such as `botpressBotId`, Voiceflow project IDs, and handoff rules.
